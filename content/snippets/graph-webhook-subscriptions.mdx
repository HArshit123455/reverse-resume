## Context

Microsoft Graph delivers change notifications to a public endpoint and cannot send an API key. It also validates a new subscription by calling the endpoint with a `validationToken` that must be echoed back exactly, and it expects a fast response. Subscriptions last at most about a week and can be deleted on Microsoft's side.

## What this proves

- Trust rests on a random per-subscription `clientState` compared in constant time, and the tenant is always resolved from the database, so a forged body can't choose where mail goes.
- Answering 202 after only verifying and enqueuing keeps the endpoint inside Graph's response budget; the actual data comes from a delta query on the inbox (not `/messages`, which would also ingest Sent Items), hydrated with `$batch` 20 at a time.
- A subscription Microsoft removed is recreated instead of failing every six hours, and lifecycle events (`reauthorizationRequired`, `subscriptionRemoved`, `missed`) map to renew, recreate and reconcile.
